# 手机助手静态资源与直连设计（2026-10-31）

状态：用户已选择“内置外壳资源，插件静态资源按版本缓存”；本设计已于 2026-10-31 获用户批准，代码及本地验证已完成，等待安装后蜂窝验收。

## 场景与主要矛盾

场景是手机通过有较高延迟、可能受代理影响的加密中继操作同一工作台。主要矛盾是连接建立后仍需跨中继重复下载不变的页面代码，且多次串行初始化放大 RTT。安全认证与实时业务必须继续在工作台执行。目标是减少首页必需传输量和串行往返，而非另写一套插件业务。

已知证据：当前外壳 JS/CSS 原始 183434 字节，gzip 后约 44790 字节。每个 RPC 人为延迟 1000ms 的临时夹具中，首页初始化约 3349ms，偏好、插件、桌面列表串行，SSE 首次连接还重复获取插件列表。实机中继存在明显 RTT 与丢包；不能把所有页面等待归因于静态下载。

## 选择与边界

已比较：只缓存资源实现较小但首次仍下载；内置同一构建的外壳且按版本缓存插件可同时改善首次外壳与重复插件加载。用户选择后者。不采用 file:// 本地站点或第二套 H5，因为这会改变现有 HTTPS、Cookie、CSP 与插件消息来源契约。

仅调整 web 构建、浏览器适配、静态服务及 web-access 手机/电脑助手和直接相关测试；不改 desk 源码、各插件正文、账号权限或任意端口策略。资源仍由同一 Web 源码生成。所有本设计中的具体实现选择均是实施建议，未经单独承诺的性能数字不是实机保证。

## 1. 同一构建的外壳内置助手

- Web 构建生成 app.js、app.css 和其内容 SHA-256 版本清单；助手构建复制该构建为 SwiftPM 资源。构建顺序先 Web 后 Swift，确保同一产物；生成物不作为人工维护源码。
- HTTPS 主文档仍经已认证、已钉扎的工作台链路获取，保持原来源。助手只在自身固定工作台主文档请求中携带内置资源版本；服务器只在版本完全一致时返回带版本标记、无需网络脚本样式的最小 HTML。
- 原生 WKUserScript 在主文档结束时检查精确工作台 origin 和版本标记，注入内置 CSS 以及同一 app.js 的异步封装。现有 HTTPS 策略与插件独立 origin 不改变，不放宽 CSP。
- 文件缺失、版本不匹配或内置资源验证失败：不协商内置模式，正常下载远程外壳。若协商后初始化失败，记录 ERROR 元数据并仅重试普通主文档一次，避免白屏或循环重试。日志不得含认证信息、URL 查询参数或页面内容。
- 只内置不含用户数据的代码、样式和固定图形；动态插件图标以及用户覆盖图标保持原读取方式，本次不冒充静态内置内容。

## 2. 插件按内容版本缓存

- 服务端根据包 integrity.json 的内容摘要确定包资源版本。对无完整性清单的兼容旧包保留原始 no-store 行为，不仅凭容易复用的 version 字段启用长缓存。
- Web 专用适配返回版本化的 view.entry，例如 __assets/<包摘要>/<原入口>；pluginOrigin 仍是纯 HTTPS origin，配置页面等所有已声明视图同样处理。相对 JS/CSS/字体/图片继续位于同一版本前缀下；插件正文无需修改。绝对资源路径仍可使用原路径且不缓存，明确保留该限制。
- 服务端验证版本和包路径边界后，对包内明确属于静态文件类型的 GET 响应使用 private、带上限的长缓存；/api、登录、RPC、SSE、上传、下载、业务 JSON、用户文件、错误响应保持 no-store。原路径保持原语义，不能因任意 URL 提供摘要而启用缓存。
- 已登录且插件已启用后才发布其视图入口；服务端每次真实访问仍检查账号、远程服务授权和启用状态，并在异步读取后复核撤销。撤销事件继续移除已加载 frame，后端 RPC 一律重新验证。静态缓存不授予离线操作或工作台权限。
- 缓存键包含服务 origin、包摘要和路径；升级包摘要改变，不复用旧代码。同版本不同内容也必须失效。不得跨插件、跨配对工作台复用。

## 3. 跨连接缓存所需的助手调整

现有随机本地端口和 nonPersistent 存储会使缓存无法跨连接复用。采用每个配对工作台独立的 WebKit 数据存储标识；标识由已保存的 hostId 派生，不新增第二份设备身份。只允许 HTTP 静态缓存跨连接保留，进入新连接前清除 Cookie、Local/Session Storage、IndexedDB、Service Worker 等非缓存站点数据并等待清理完成，保持原来跨连接不复用业务会话的行为。正常连接期间不清理当前页面状态。

每个 hostId + serviceId 派生稳定的高位 loopback 端口，仍只绑定 127.0.0.1 且禁止复用。占用或碰撞时记录 INFO 并回退系统随机端口；宁可缓存未命中也不连接占用者。绝不为了缓存允许客户端指定任意服务或 origin。断开、禁用及退出仍关闭当前实例监听器与流，不残留代理。取消配对或认证被撤销时清理该工作台全部缓存；清理异常记 ERROR、禁止把清理失败当作恢复授权。

## 4. 初始化与实时数据

Web 适配层在认证成功后立即预取只读的偏好和桌面列表，插件列表等待首次 SSE 订阅建立后立即预取，三个读取重叠执行，并将各自结果只提供给首次对应调用；不持久缓存业务数据。预取失败继续遵循原调用错误，不伪装空成功，不产生未处理拒绝。后续读取及写操作仍正常 RPC。SSE 初次 onopen 不重复发布 plugins.changed，重连仍刷新；真实变更事件始终照常发布。测试必须覆盖事件与预取竞争，避免用旧快照覆盖新状态。该项限定在 web 适配层，不修改共享 renderer 的执行流程。

2026-10-31 19:17 验证：worker PID 84004 的新 TCP 本地端口 53522 对应同一中继，Clash 链路为 [DIRECT]，已有双向字节；OpenAI 实际连接命中 DomainSuffix 并经过 AI 组，连接表内非 OpenAI 代理连接为 0。证据为 /tmp/work-desk-clash-openai-only-result-20261031.json；备份位于 Clash 数据目录 backups/openai-only-1793445362499。未以手机重新连接验证蜂窝完整功能，也没有据此断言所有 UDP/P2P 实际路径已逐条测试。
