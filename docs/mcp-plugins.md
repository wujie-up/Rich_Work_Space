# MCP 服务与 AI 接入

MCP 插件管理独立部署的 MCP 服务，不在插件内编写服务代码。例如 SLS 查询服务由独立 MCP 服务实现，在这里配置它的地址与密钥即可接入，无须再开发 SLS 桌面插件。

1. 打开「MCP 服务」，填写名称、远程 Streamable HTTP 地址和密钥，点击「保存并启用」。密钥按 Bearer 认证发送；无认证服务可以留空。其他认证方式可在高级请求头中填写。
2. 启用后可以发现工具、用 JSON 参数试调用、查看脱敏日志。错误密钥会显示失败状态，可修改后重新启用。
3. 运行中的服务自动接入 AI，无须再勾选。AI Agent 新建、恢复或分叉 Codex 会话时获取最新工具入口；停止的服务不会注入后续会话。已运行的会话不热更新工具配置。

仍支持原有 stdio 可执行文件、JSON 参数数组、绝对工作目录和环境变量配置。启用远程服务表示连接已经部署的服务，不会替用户部署远程进程。插件重启后需重新启用服务。

每个下游客户端有独立上游连接；管理界面试调用使用另一连接。AI 仅获取本机网关地址和临时认证令牌，不获取上游密钥。网关仅监听 127.0.0.1。配置、认证请求头和日志仍保存在插件私有目录；密钥未加密存储，日志会脱敏，日志保留约 1 MiB。

兼容范围为 2025-11-25 会话型 MCP、stdio 与 Streamable HTTP，以及 tools/resources/prompts 和列表变更通知。本版不支持 OAuth、旧 SSE 专用服务、2026 无状态协议、sampling/roots、自定义 CLI 自动适配或运行中会话热更新。
上游握手和普通请求有十八秒期限；已建立的远程通知流不受普通请求期限限制。普通下游流断开允许约两秒重连；没有事件流的下游会话在三十秒无请求后回收，下次客户端需重新初始化。停止、异常退出和插件卸载只清理该插件登记的进程组。

## 保留数据升级

安装包为 `mcp-services-0.2.1.plg`，使用标准 gzip tar 格式，插件 ID 仍为 `mcp-services`、dataVersion 仍为 1。在插件中心选择「保留数据」卸载旧 MCP 插件，再导入新版包；不要选择删除数据。桌面更新不会自动替换已安装插件。

现有 services.json、stdio 配置、认证请求头、日志以及 AI 配置沿用原格式，不做迁移。旧的本插件服务选择文件保留，但启动 AI 时按当前运行状态自动接入；外部提供方仍使用原有显式选择。

从独立 Adapter 升级时，先按「保留数据」卸载旧 `ai-mcp-adapter`，避免同时出现两个接入提供者。MCP「AI 接入」保留旧配置导入功能，可手动选择旧 `plugin-data/ai-mcp-adapter/config.json`；导入仅替换服务选择，原文件保留。新配置位于 `plugin-data/mcp-services/ai-config.json`，不会改写 Codex 用户配置。
