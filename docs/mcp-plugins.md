# MCP 服务与 AI 接入

MCP 插件管理 Python/JavaScript 代码、配置及运行，也支持已有 stdio 和远程 Streamable HTTP 服务。运行环境与依赖需预先准备，详见 [服务开发规范](mcp-service-development.md)。

## 使用

维护服务代码和配置后，使用保存、调试、启用、停用、删除。已部署代码可重新加载编辑，入口修改保留同目录辅助文件。运行时允许保存；校验通过后停止旧实例，手动启用新配置。无效输入不影响正在运行的实例。

管理界面没有发现工具、工具选择和 JSON 调用参数。MCP 服务本身定义工具，AI 通过工作台按需读取其说明并决定调用。打开页面、保存和启用均不预读工具。

调试使用编辑区当前代码和配置创建临时实例，由 AI 验证发现和调用。用户可填写自然语言目标，需要业务信息时由 AI 提问；操作仍遵循工作台审批。结果展示真实发现数量、调用次数和上游返回，AI 文本不能代替调用证据。完成、取消或插件停止后清理临时进程、部署及 AI 任务；不修改正式定义或启用状态。

## 兼容与升级

当前包为 mcp-services 0.4.7、AI Agent 0.6.7，生成在 plugin-dev/dist/。插件 ID、dataVersion 及旧 mcp.connections.v1、agent.launch-config.v1 契约不变。独立 AI 对话沿用现有工作台网关，菜单任务限制保持不变；AI 仅新增目标限定的调试任务入口。

工作台能力按服务延迟发布两个适配能力：工具说明读取上游 tools/list，调用工具转发实际 tools/call；不要求用户注册工具。正式 AI 会话无法发现临时调试服务。每个下游 MCP 客户端仍使用独立上游连接。

升级保留 plugin-data/mcp-services 中的代码修订、配置、密钥、日志及 AI 配置；不改写系统 Agent 配置。desired-services.json 记录期望运行的正式服务，重启后恢复，手动停用清除。配置值保存在本机文件，日志按配置值脱敏。

仅兼容现有 stdio 和会话型 Streamable HTTP；不增加 OAuth、旧 SSE、依赖自动安装或系统 CLI/认证导入。网关仅监听 127.0.0.1，停止和禁用只清理本插件登记的进程。协议链路测试与真实模型调用验收分别报告。
