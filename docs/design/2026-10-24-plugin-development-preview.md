# 工作台内插件开发与独立预览

状态：历史方案，已按后续用户要求移除工作台内插件开发及预览代码。当前流程为在 `plugin-dev/` 开发、打包，再导入正式插件；以下仅保留设计背景，不作为现行开发规范。

## 场景与主要矛盾

场景是用户在同一个 DeckPg 工作台内，让 Agent 编写插件，并反复预览、测试和修改；其他已安装插件继续处理原有任务。

主要矛盾是开发版需要频繁替换代码、失败和重启，而正式插件需要稳定运行并保留数据。解决重点是开发预览的运行身份、数据和生命周期隔离，而不是再启动一个工作台。

用户已选择：同工作台内提供开发版独立预览和测试数据，其他插件继续运行。

## 已检查的现状

- AI 插件已有工作目录选择、Agent 对话、命令行引擎和历史能力，可复用。
- 宿主已为插件提供独立后台进程、沙箱 frame、包校验和生命周期管理。
- 当前插件注册、事件、协议来源和数据目录均以插件 ID 为身份；直接安装同 ID 开发版会与正式版冲突。
- 独立后台进程提供故障隔离，不是恶意代码的文件权限沙箱。开发预览仍仅执行用户明确选择的可信本地代码。

## 路径选择

1. 只让 Agent 写代码，用户另行打包导入：改动少，但无法满足已选择的工作台内独立预览。
2. 同工作台增加独立开发预览空间：复用现有 Agent 与插件运行机制，新增预览身份和数据隔离。采用此路径。
3. 启动第二个开发工作台：容易复用完整安装流程，但不符合单工作台内预览的目标，也增加版本和窗口管理负担。

## 用户流程

1. 插件管理内容区增加“开发插件”入口，不放进桌面/插件/主题导航同一行。进入轻量开发面板，选择开发目录。
2. 面板通过现有插件入口机制打开 AI 插件的开发对话，并传入用户选择的开发目录。宿主不识别具体 AI 引擎，也不承载提示词或编程逻辑。
3. AI 插件复用现有对话能力，提供插件开发约束和包格式上下文；Agent 在该目录编写、构建插件。已有项目直接继续，新项目由 Agent 按现有规范生成。
4. 用户明确点击“预览”或“重载”，选择项目中已构建的插件目录或 `.plg`。宿主校验并复制为运行快照，再启动开发版窗口，窗口明确标记“开发预览”。
5. 用户可以同时操作正式插件、Agent 对话和开发预览。再次重载只替换该开发版的运行快照，不重启 Agent 或工作台。
6. 面板提供停止预览、显式清空测试数据、定位开发目录。清空测试数据先停止目标预览并确认；普通重载保留测试数据。
7. 完成后由 Agent 复用现有打包脚本生成 `.plg`。用户另行导入正式版本，不自动覆盖正式插件。

交互使用既有简洁 SVG 线条按钮，保留准确提示和无障碍标签；支持中英文。具体尺寸与排版复用现有设置界面，由实现者决定。

## 运行与数据设计

### 独立开发空间

- 每个开发项目绑定宿主生成的稳定 `developmentId`，源路径通过用户选择并保存；插件不能自行指定任意空间身份或正式数据目录。
- 每个开发空间复用独立的 `Storage` 与 `Plugins` 实例，根目录位于工作台数据目录的 `development/<developmentId>/` 下。
- 开发插件保留原始清单 ID。宿主路由、事件、窗口和界面来源以“空间＋插件 ID＋运行代次”区分；正式空间作为现有默认值，保持兼容。
- 同 ID 正式版与开发版可共存。开发版拥有独立配置、历史、日志、能力注册及调用记录；不能通过宿主 API 读取正式数据。
- 开发预览默认仅发现本开发空间内的服务与能力，不接入正式插件的能力目录。第一版允许一个项目预览一个待开发插件；多插件联调不在本次范围。
- 项目记录与测试数据保留，退出时停止开发进程；重启工作台后不自动执行开发代码，需用户再次点击预览。

### 加载与重载

- 不把源码目录当安装目录；复用现有包校验和导入流程，将构建产物复制到开发空间的独立快照。
- 禁止选择正式插件安装目录或正式用户数据目录作为开发源码/预览来源；按真实路径识别符号链接，避免误改生产数据。
- 先校验并准备新快照，成功后才停止旧开发实例并切换。校验失败保留旧实例；激活失败记录目标空间、插件 ID、代次及错误，并允许修正后重试。
- 不增加宿主自动执行项目构建命令或全仓库监听。构建由 Agent 的既有引擎及权限确认处理，用户明确重载，避免写入中间状态时反复启动。
- 停止、超时、崩溃及清理仅作用于目标开发实例登记的进程和 frame，拒绝已失效代次的请求与事件。

### 界面与调用边界

- 开发版拥有与正式版不同的站点来源；协议处理、frame 调用、事件订阅和 renderer 故障监测均按所属空间查找目标。
- frame 只能操作其所属插件；开发管理命令由宿主用户操作发起，插件 frame 不获得任意目录导入、删除空间等管理权限。
- Agent 仍在正式 AI 插件的进程与数据空间运行；仅其开发会话的工作目录指向源码。Agent 代码不移入 `desk/`，开发预览重载不结束该会话。
- AI 插件未启用时显示启用入口；不会自动安装其他引擎、复制系统认证或重启已有 Agent 任务。

## 修改边界

- 宿主：新增通用开发预览管理；直接关联的插件路由、协议、IPC/preload、frame 归属与故障处理；插件管理开发入口、窗口标记和中英文文案。
- AI 插件：开发会话入口与开发上下文，复用现有对话、引擎、授权和历史；更新插件版本并构建 `.plg`。
- 文档：插件开发协议及使用说明；必要的开发隔离约束。
- 验证：新增宿主开发空间单元测试、边界集成夹具和 AI 开发入口测试，仅运行这些受影响领域及直接关联契约测试。
- 不调整无关业务插件、图标拖动、正式版本更新策略，不清理现有数据，不提交或上传代码。本次不自动重装应用，交付可验证的构建与插件包。

## 可验证的验收结果

1. 在同一工作台中打开开发 Agent、同 ID 正式插件和开发预览，三者可分别操作，窗口身份明确。
2. 开发版写入、重载、停止及清空测试数据后，正式版配置与历史内容不变；普通重载后开发测试数据仍可读。
3. 重复重载开发版时，旁侧夹具插件后台 PID 和界面状态保持，现有任务继续执行；Agent 会话不中断。
4. 开发版后台崩溃、挂起或界面进程崩溃后，故障只标记开发实例；正式版和其他插件仍能完成一次操作。
5. 关闭目标预览只回收其当前登记的进程；迟到事件、旧 frame 请求及同 ID 跨空间调用被拒绝。
6. 无效包、越界路径或选择正式安装/数据目录时不给予执行；错误不停止现有有效预览。
7. 无插件时宿主仍可用；开发退出后重新启动宿主不自动加载开发代码；正常运行仍只有一个工作台实例。
8. 构建受影响的宿主资源和新版 AI 插件 `.plg`，交付实际命令、结果、版本、路径及未覆盖的平台/真实引擎验证项。

以上指标覆盖应用管理范围内的故障与数据隔离；不承诺约束任意可信 Node 插件主动访问系统文件，也不承诺系统资源耗尽时其他进程完全不受影响。
