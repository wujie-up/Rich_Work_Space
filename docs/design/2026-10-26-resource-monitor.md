# 插件资源监控设计

状态：用户已确认；已实现并生成交付物，验证结果见同目录 resource-monitor-verification 文档。

## 目标与已确认交互

用户希望监控各插件的 CPU、内存、网络等资源，在桌面最外层展示图表。已确认：面板悬浮在插件窗口上方，可以最小化为小横条。

本次在 `plugin-dev/resource-monitor/` 创建独立插件，稳定 ID 为 `resource-monitor`，首版版本为 `0.1.0`。沿用项目 Node ESM、原生 HTML/CSS/JavaScript 和现有构建工具。不修改或安装用户正在使用的插件，不提交代码。

## 方案比较与选择

1. 普通插件窗口：可复用现有窗口，但无法保证悬浮层级和横条形态，不符合已确认交互。
2. 桌面背景挂件：遮挡较少，但会被业务窗口覆盖，用户已选择悬浮方案。
3. 通用桌面悬浮视图：宿主提供沙箱挂载、层级、位置和收起外壳；监控插件提供指标与图表。采用此方案。

悬浮指工作台内部高于插件窗口，不跨应用置顶，不覆盖工作台设置和确认弹窗。

## 展示与配置

以下为实现建议，待本设计确认：

- 默认在工作台右上角显示约 380×320 的面板；可拖动，位置限制在可见桌面内，缩放窗口时自动调整。
- 展开后显示插件合计 CPU、内存、网络上传/下载速率的近期曲线，以及各插件当前数值；按 CPU 或内存排序，可选中插件查看对应曲线。
- 收起后显示约 340×36 的小横条，保留 CPU、内存、上传/下载数值和展开按钮；采样继续。狭窄桌面允许隐藏次要文字，不能超出可见区域。
- 默认每 2 秒更新，内存中保留最近 120 个采样点；首个无差分基线的速率显示“采集中”，不可得指标显示“不可用”及原因，不伪造为零。
- 设置页仅包含采样间隔（2/5/10 秒）和默认展开状态。面板位置、收起状态及设置分别按插件 ID 保存；不持久化进程 PID、资源历史或网络连接详情。
- 普通窗口和平铺视图可打开同一监控内容；与悬浮面板共享后台采样，不重复创建采集器。
- 黑白线条图表适配浅色/深色主题，曲线使用文字标签、实虚线区分。按钮使用 SVG，具备 aria-label、title 和键盘操作；图表同时提供可读数值。
- 外壳展示插件名称，正文从指标开始，不重复名称或品牌。

## 领域边界与宿主契约

宿主仅新增可被其他插件复用的两类机制，并声明新的 requiredHostFeatures：

1. 通用悬浮视图声明与挂载：复用现有独立 origin、sandbox frame、桥接和主题协议。由宿主管理外壳拖动、收起、恢复与生命周期；不得静态导入 resource-monitor 业务实现。旧插件清单行为不变。
2. 只读运行实例目录：向调用方提供稳定插件 ID、显示名称、当前状态、运行实例 ID、当前后台 PID 及该实例登记的子进程根 PID。只返回当前运行实例，接口不负责 CPU/内存/网络采集，不返回目录、配置、密钥或历史 PID；禁止将监控结果用于进程终止。

目录调用通过受校验、带期限的后台请求实现，不允许插件自报另一调用方身份。是否启用插件只依据现有宿主记录。请求不得激活被监控的按需插件。

新清单为 application / showIcon:true / loadOnStartup:true / background:service。启用后挂载悬浮视图；没有安装监控插件时不出现悬浮外壳。正式关闭通过宿主现有确认流程停止采样并移除全部监控视图；默认保留设置，重新打开后恢复。关闭文案由清单提供。

## 采样口径和平台实现

- 首版针对当前 macOS 环境实现并验证；OS 入口集中在插件 `src/main/os/index.js`，macOS 实现在 `os/mac/`。未验证的平台返回明确不支持状态，不宣称支持。
- 插件以只读方式采集当前用户可见的系统进程数据；利用宿主目录中的后台根和登记子进程根，结合当前进程父子关系归属。相同 PID 只计一次；已退出实例移除，实例更换时重置差分基线。
- CPU 为采样期间进程 CPU 时间增量除以实际墙钟时间，统一按整机逻辑核心数归一化到 0–100%；内存为 RSS 字节。同一进程树先去重再合计，并明确 RSS 可能包含共享页。
- macOS 网络使用系统提供的按进程计数进行上传/下载差分。实现时验证当前系统工具的输出、权限和计数稳定性，不提权、不安装抓包证书、不采集正文；失败时仅网络项不可用，CPU/内存继续更新。短命进程可能来不及采样，界面/说明注明采样估计。
- Electron 的共享 renderer 或网络服务进程无法可靠按插件拆分时，不将共享占用全部计入任一插件，也不重复累加。首版插件统计范围明确为“后台及可归属子进程”；共享界面/网络进程不计入插件合计，界面可见此口径。
- 监控插件自身同样列入统计。采集器所用进程属于监控实例，退出时仅停止自己持有的实时句柄；不登记其他插件 PID 为 ownProcesses。
- 采用单一有界采样循环，上一轮未完成不重叠启动。命令使用可执行文件和参数数组，限制超时及输出大小。失败保留错误状态与最后采样时间，不沿用旧值冒充实时数据。

## 故障、数据和生命周期

实现、资源、配置、测试全部归属 resource-monitor。插件停止、禁用、卸载或工作台退出时阻断新采样，清理定时器和采集命令。监控故障不得改变被监控插件状态或终止其进程。后台异常采用现有插件故障记录和重新启用流程；悬浮视图失效时仍可通过插件中心恢复。

数据保存在 `plugin-data/resource-monitor/`；默认卸载保留。现有插件的数据和运行进程不作为测试目标。保留现有工作区未提交改动。

## 实施范围与验证

必要改动为新插件，以及 desk 中通用清单校验、后台只读请求、沙箱悬浮外壳和直接关联文档与测试。避免改动无关插件和系统应用安装。

新插件依赖新增宿主协议，不能只交付一个旧安装版无法导入的 `.plg`。本次一并构建兼容的 macOS arm64 宿主安装包，放在仓库既有 `desk/dist/releases.noindex/` 输出目录；不自动替换 `/Applications/DeckPg.app`。宿主版本在实施时按当前版本递增补丁号（当前读取到 0.1.16，预期 0.1.17），旧宿主对新插件应明确提示需要升级。验收使用隔离数据目录和新宿主构建产物；交付同时注明安装包与插件包路径、先更新宿主再导入插件的顺序。

因新增跨领域契约和视图生命周期，在插件领域测试之外增加相关宿主契约测试和临时数据目录的 Electron 集成验证：

- 合成进程树归属、去重、CPU/网络差分、重启/PID 变化、缺失权限、命令超时和采样不重叠。
- 无插件空桌面；悬浮层高于业务窗口且低于确认弹窗；拖动、边界适配、收起横条和恢复；普通、平铺与设置页面。
- 一个插件后台/界面崩溃后宿主和另一测试插件仍可操作；停止监控仅关闭监控采集器；停用/关闭后不再采样；保留数据重装可读设置。
- 使用隔离测试插件制造 CPU/内存/网络活动，区分解析单测、系统实测及真实宿主实测；无法可靠归属的统计不声称已覆盖。
- 运行受影响的必要测试、`npm run build`、`npm run pack:plugin -- plugin-dev/resource-monitor`，检查标准 gzip tar、清单及 integrity.json；按仓库要求执行 macOS 安装登记检查。交付 `.plg` 路径、版本、宿主协议变更与未覆盖项，不自动安装或发布。
