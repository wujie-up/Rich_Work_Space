# 需求与研发设计联合审核：循环输入优化

本次处理多轮文档审核场景：必须保留完整需求基线和当前设计稿，但重复传输原稿、历次修订稿和评审全文会使输入不断增长。

新版模板仅向修订节点传入一份当前设计稿、需求基线、协调后的未解决问题和本轮用户决定。四方评审仍独立进行，协调结果必须保留少数意见、稳定问题编号和来源；各角色原始评审和原文保存在运行记录及检查点中。修订记录只描述本轮修改，不重复历史正文。

## 使用

1. 更新 AI Agent 至 0.6.53、工作流至 0.5.38。
2. 导入同目录的 `requirements-design-review.workflow.json`，核对导入目标后启动新运行。
3. 已有运行使用启动时的流程快照，不会自动替换节点提示词。原模板、历史和检查点不变。

工作流新增 `{{当前值 ?? 首轮值}}` 空值回退表达式，用于首轮读取原稿、后续读取当前修订稿。普通占位符及原有类型传递保持兼容。

## 长输入与压缩

AI Agent 移除任务接口 90,000 字符和会话发送 100,000 字符的额外限制，完整当前输入交给引擎。节点绑定的原生会话继续复用，历史上下文压缩由引擎原生机制管理；插件不截断正文、不插入额外压缩指令。

工作台仍有 1 MiB 的单次 JSON 输入传输上限。工作流会在调用前明确显示实际字节数及上限；若旧 AI 提供方仍声明字符上限，也会显示实际字符数及提供方上限。移除字符限制不代表模型可以接受无限长的单次输入。

## 验证

74 项相关测试通过，覆盖三轮长文评审、当前稿只传一次、后续轮次输入不随历史累积增长、原文检查点保留、150,000 字符原样交给原生会话，以及会话复用、人工确认和中断续跑。压缩验证覆盖协议事件的接收与任务继续执行，未实际触发在线模型的上下文压缩。
