# 验证记录

日期：2026-10-30。使用当前工作流 Engine、导入协议与节点注册表；交付 work-flow 0.5.42。

## 本次修复

场景是多角色对阶段产物反复评审。主要问题是文档评审混入后续运行验收项、批次轮数可续加，以及缺少稳定问题编号与修改／校验证据的闭环。旧运行里既有真实修改，也存在后期无进展；不能仅凭轮数推断作者没有修改。

- 前三阶段按文档交接条件评分，后续运行验收要求保留在 `futureAcceptance`，不降低最终验收标准。
- 作者逐项记录问题编号、修改位置、校验方式与证据；各角色独立复核，协调 Agent 汇总累积已验证关闭的问题编号。下一轮携带上轮问题及修改记录。
- 模板每个循环总计最多 5 轮，达到上限保存并暂停，不能追加第 6 轮。首次完整评审建立基线，随后连续两轮没有新增已验证关闭的问题则提前暂停。
- 引擎新增可选总上限和无进展上限，默认关闭；旧模板仍保留批次确认行为。检查点保留额度及进展；文件重选、嵌套循环与成功旁路重入不清零。

本次修改仅涉及 work-flow 引擎、关联界面、版本及测试，以及本目录的模板定义、生成物和说明。未修改工作台或 AI Agent；未安装到当前 DeckPg，未更改用户模板或流程数据，未执行提交。

## 验证边界与使用方式

自动测试替换了外部模型返回；调度、路由、并行、人工确认接口、检查点恢复和文件写出使用真实 Engine。没有启动真实模型进行项目开发、浏览器集成测试或后台数据验收。

修改内容是否真实解决问题、检查项适用性、证据是否充分，由独立评审和协调 Agent 判断；引擎确定性执行输出字段校验、路由及预算限制，不代替模型判断证据语义，也不独立重算逐项比例。原有 90% 且无阻断的放行条件不变。

旧运行保存的是旧流程快照。使用新规则需更新工作流定义并新建运行；安装包和 JSON 不会主动覆盖已有模板及历史。达到总上限只表示保存并暂停，不表示评审通过；应检查问题与证据后调整资料或流程，再新建运行。
