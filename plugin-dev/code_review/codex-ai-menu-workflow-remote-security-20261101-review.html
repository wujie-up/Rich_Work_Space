主要问题与建议

中等 · 优先处理

1. 原生传输库包含已披露漏洞版本 Tokio 1.54.0

已确认依赖版本；未复现内存漏洞利用

电脑已安装插件的原生 .node 文件与源码依赖二进制 SHA-256 一致，二进制内含 tokio-1.54.0。手机 0.1.23 构建目录的 DeskLinkIOS.debug.dylib 同样包含该版本；实际构建使用的 Cargo.lock 也锁定 1.54.0。官方 RUSTSEC-2026-0384 / CVE-2026-115567 描述多线程运行时 Interval 与时间驱动之间的竞态，可导致崩溃、use-after-free 或堆内存损坏。公告评级为中等；本次没有证明远程可控触发、代码执行或解密能力。

建议：两端原生库应升级到 Tokio ≥1.54.1 的修复版本并重新构建或使用经过核验的上游修复产物。只更新 JavaScript/Swift 外层应用版本不能修复静态链接依赖。

官方公告

中等 · 条件性

2. ctutils 0.4.3 命中恒定时间运算公告

版本与依赖路径已确认；产品可利用性未证实

Rust 锁文件含 ctutils 0.4.3，iroh 1.4.1 直接依赖它。核对 crates.io 的同版本源包，src/tls/misc.rs:119 使用 CtEq 比较 Blake3 HMAC。RUSTSEC-2026-0385 披露部分 Choice 掩码生成可能出现依赖秘密值的分支；另一个 u128 比较问题限于 32 位目标。本产品为 Apple arm64，不能把 32 位问题直接套用；也尚未证明此处数组比较经过有问题的掩码路径，因此不判为已证实密钥泄漏。

建议：与原生传输库升级一起纳入 ctutils ≥0.4.4；如暂不能升级，需检查具体单态化函数及 arm64 汇编后决定是否豁免。

3. 未认证连接能够占用全部远程接入名额

隔离调度夹具已复核；未向生产端点实施压测

AccessService.accept 在身份确认之前把连接计入全局 connections；达到 32 后直接拒绝新连接。隔离夹具保持 32 个未完成认证的 serve 调用，第 33 次接入被拒绝（accepted=32, refused=1）。握手及控制帧有超时，已有连接不会因此自动被解密或获得权限；但知道主机端点的攻击者持续补充连接，仍可能阻断合法手机建立新连接。本次没有测量真实网络持续攻击成本。

建议：将未认证连接与已授权连接分开预算，加入未认证握手总速率限制，并评估为已绑定设备保留接入机会；保留现有超时和全局硬上限。

官方公告

已验证的安全边界

  • 免登录凭据只在已建立的受控传输接收器中签发；普通 LAN 请求仍需账号认证。会话摘要绑定到具体 grant，不能把 A 手机 Cookie 移到 B 手机或 LAN 使用。
  • 绑定使用短期随机邀请、HMAC 挑战及本机指纹确认；手机验证连接对端身份。配对创建、批准、撤销等管理方法声明 nativeOnly，宿主拒绝网页或伪造参数取得该上下文；exclusive 防止这些管理方法并发执行。
  • 撤销先移除已批准设备、关闭 QUIC 与转发套接字、撤销 grant 和 Cookie/SSE 会话；停服、哈希登录竞态、在途 RPC 和静态资源边界有直接测试。
  • 通道仅接收预先声明的 workspace / plugin 服务标识，转发至受控 Unix broker；不接收远程任意 IP、端口或宿主文件路径。Host / HTTP2 authority、Origin、CSRF、独立插件服务接口边界保留。
  • 手机 WebKit 只允许本次回环服务来源，固定受认证 QUIC 连接下发的证书 DER，并检查有效期及 Apple 信任评估；未发现“接受所有证书”逻辑。设备私钥存于解锁可用、不可迁移的 Keychain 项。
  • 诊断日志保留有上限的元数据；抽查未记录配对秘密、Cookie、私钥及业务正文。

撤销语义及剩余限制

  • 撤销阻止后续请求和连接，并断开在途传输；已经交给插件执行的操作不会自动回滚，已下载或已经显示在手机中的数据也不能远程收回。
  • 撤销持久化失败会报错并停止远程服务，当前测试验证了这一关闭策略；不能把报错的撤销当成持久化成功，旧磁盘授权可能在重启后被重新读取。
  • “仅工作台服务”是网络服务边界，不是只读权限：已绑定手机拥有工作台及已启用可信插件的既有能力。恶意插件、本机已失陷、手机已解锁被他人使用不由传输加密解决。
  • 中继或 VPN 可能观察端点、时序及流量大小，能够干扰可用性；身份验证和证书固定的代码边界可阻止一般中间人冒充，不能保证零漏洞。
  • 本次没有公网独立攻击机渗透、实机恶意证书注入、依赖漏洞利用复现或原生库全量 SBOM/汇编审计；没有审计全部插件业务代码，也没有重新构建或更换当前运行服务。
