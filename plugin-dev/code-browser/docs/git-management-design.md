# coding 常用 Git 管理

场景：用户与 Agent 在同一工作台内查看、修改和协作维护本地 Git 仓库。主要矛盾是 coding 只有只读对比，日常分支与提交操作需要离开插件，而新增写操作又必须避免覆盖本地修改及干扰正在运行的 Agent。方案围绕操作闭环、明确影响及仓库互斥展开。

## 范围与方案

只修改 plugin-dev/code-browser 的 Git 后台、能力声明、界面、相关测试、说明和版本；不修改 ai-agent，不导入其他插件内部代码。宿主通用资源契约存在下述阻塞，需确认后调整 desk 的必要关联代码。沿用现有 Git CLI 和通用控件，不增加 Git 引擎、编辑器或图标库。

采用结构化操作面板：命令白名单、参数校验、明确的执行结果。相比提供任意 Git 命令输入框，结构化操作能显示目标分支、文件和影响并限制误操作；相比引入完整 Git 客户端，保持包体与运行成本较低。

| 范围 | 支持操作及默认行为 |
| --- | --- |
| 状态与分支 | 当前分支、工作区/暂存区/未跟踪/冲突文件、本地与远程分支；沿用 Agent 的分层分支树，标记当前分支；刷新、切换、新建、重命名、安全删除；远程分支可创建本地跟踪分支 |
| 更新与推送 | fetch、pull、push、首次推送设置 upstream；选择已配置 remote；pull 默认只允许快进，分叉时用户显式选择 merge 或 rebase；不默认强推、不自动修改凭据 |
| 暂存与提交 | 按选中文件或全部暂存、取消暂存、输入说明后提交；提交仅包含暂存内容；不自动配置 Git 用户身份 |
| 集成 | merge、rebase、cherry-pick；展示冲突文件与状态，在外部编辑器解决并回 coding 暂存后继续，或中止；不提供自动冲突选边 |
| 储藏 | stash 保存（可包含未跟踪文件）、列表、应用、弹出和删除 |
| 回滚 | revert 指定提交，新增撤销提交、保留历史；reset 提供 soft/mixed/hard 并说明区别；丢弃选中已跟踪文件的修改。hard reset、丢弃修改、删除 stash 必须二次确认并显示影响 |
| 原有能力 | 保留提交历史、文件读取和版本对比，操作完成后刷新受影响内容 |

不包含交互式 rebase 编辑器、自动冲突合并、子模块管理、Git LFS 管理、远程仓库创建、凭据管理、强制推送、强制删除分支或清理未跟踪文件。Git 使用用户已配置的非交互认证；认证缺失明确报错。

## 执行与保护

- Git 写操作使用规范化仓库根路径对应的通用资源键 git:<root>，与 Agent 已有占用报告互斥；Agent 忙碌时拒绝操作，提示结束本轮后重试。兼容仓库子目录与 worktree。当前 UI 方法资源锁与能力执行锁是两套路径，后台任务返回后方法锁也会释放，现有服务自调用又被循环保护拒绝，因此不能仅靠 coding 内部状态保证跨插件安全。
- 必要关联调整：desk/src/main/common/plugins.js、capabilities.js 及必要的 worker/runtime 桥接，提供入口一致、可取消、生命周期有界的通用资源占用机制，锁覆盖 Git 实际进程生命周期；更新直接关联的契约测试与 docs/plugin-api.md。desk 仅实现通用资源协议，不包含 Git 命令或插件 ID 特判。此必要关联范围已由用户确认。
- coding 内同一时间只允许一个 Git 写任务；Maven 编译、项目切换与 Git 写任务互斥。只读查询维持现有限制。
- 普通切换保留未提交修改，Git 拒绝覆盖时原样反馈；merge/rebase/revert 等集成操作要求干净工作区，不隐式 stash 或 reset。
- 冲突作为可见任务状态，显示冲突路径并允许继续/中止；操作失败仍重新读取仓库状态，不把部分执行当作成功。revert 合并提交需显式主线父编号。
- 网络操作与可能较长的本地操作使用后台任务、有限日志和取消，不阻塞界面 RPC；停止插件只清理本实例登记的进程。取消不承诺恢复磁盘状态，重新读取状态并提示可能的未完成操作。
- Agent 通过 desk.capabilities.v1 调用相同领域实现，写操作声明影响、要求宿主确认、禁止自动重试，使用同一资源互斥；不开放任意 shell 命令。
- Git hooks/过滤器可能执行项目配置的代码，写操作将如实说明 process.execute 等影响；不自动绕过签名或提交校验。日志包含插件 ID、任务 ID、仓库与动作，不打印认证数据。

## 界面与性能

Git 标签增加分支/状态/操作区，分支可折叠，动作按钮为简洁 SVG，title 与 aria-label 同步。文件及分支名称使用安全文本节点。复用公共控件与明暗主题，窄窗口允许换行和内部滚动。

仅进入 Git 页面、用户刷新或操作完成时读取分支/状态，不遍历源码建立 Git 索引；仅活动任务进行有限频率状态轮询，隐藏页面停止轮询，输出限量。保持文件目录按需加载。

## 验收

1. 临时仓库覆盖分支切换/跟踪/创建/删除、暂存提交、stash、合并快进/冲突/中止/继续、rebase/cherry-pick/revert、reset 三种模式及文件恢复，确认失败时本地修改保留。
2. 本地 bare remote 验证 fetch、pull、push、upstream 与拒绝非快进；不接触用户真实远程仓库。
3. 验证输入参数边界、任务取消/停用清理、同仓库并发拒绝、编译互斥，以及 Agent 能力的写影响与确认声明。
4. 真实插件包验证主要操作闭环、分层分支选择、冲突反馈、明暗主题、键盘与窄窗口；验证已有源码浏览、Java 跳转、Git 对比及 Maven 无回归。
5. 构建并生成递增版本 .plg，交付实际测试结果与未覆盖项；不提交、推送当前开发仓库。

方案已按用户确认实施；验证仅使用临时仓库及本地 bare remote，不执行当前开发仓库提交、推送。实际验证结果见交付说明。
