# Maven 项目与生命周期

场景：在 coding 中对本地 Maven 项目及模块执行构建。主要矛盾是现有固定 compile + 手填目录无法方便定位多模块项目和选择生命周期，而引入完整 IDE Maven 模型会增加成本。

沿用现有独立构建进程、日志上限、取消和编译互斥；仅扩展 coding。按需扫描项目下的 pom.xml，跳过依赖/构建目录和符号链接，最多 10000 项/10 秒/200 个项目；显示按目录层级组织的项目选择树，不解析或执行 POM 来发现项目。刷新手动触发，不持续扫描。当前目录仍可手工填写。

执行参数增加白名单 phase（默认 compile）、clean（先清理）、skipTests（跳过测试）、alsoMake（从根 POM 使用 -pl 模块路径 -am 构建依赖）。覆盖 Maven default、clean、site 三套生命周期；目标阶段由 Maven 自行执行其前置阶段，不把各阶段当成独立脚本。deploy/site-deploy 显式确认发布影响。保留 wrapper 优先策略，不允许任意命令参数。兼容既有 code.compile，扩展其 Schema，项目发现使用只读 code.mavenProjects；任务保留阶段与选项并支持刷新后继续观察。

验证：领域测试校验全部生命周期白名单、参数注入拒绝、模块与依赖构建参数、目录边界、发现上限/取消、现有取消与进程清理；真实包验证项目选择、阶段执行、日志、主题与窄窗口。构建递增版本 .plg，不提交开发仓库。实际 deploy 仅验证参数及确认流程，不向远程仓库发布。
