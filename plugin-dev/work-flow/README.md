# 工作流编排 0.5.1

工作流领域属于本插件，Agent 能力通过工作台调用 ai-agent 插件。普通节点、邮件和菜单初始化操作见 `title.md`。
分发产物：`plugin-dev/dist/work-flow-0.5.1.plg`。插件清单、package 与锁文件版本统一为 0.5.1，宿主无需升级。

## Agent 流水线

在“AI 能力”中添加“Agent 任务”，通过角色提示词区分产品、开发、评审与测试。节点仍由工作台调用 AI Agent 插件；复用既有任务接口，无需为工作流升级或扩展 AI Agent。角色、输入映射及输出解析均属于本插件的 Agent 节点。

- 输入：直接填写文本，或填写输入映射 JSON，例如 `{"requirement":"{{source.text}}","design":"{{design.output}}"}`。使用画布节点的实际 ID；完整变量引用保留对象、布尔和数字类型。
- 输出：留空保持原有文本输出。固定字段示例 `{"passed":"boolean","summary":"string","issues":"string[]","route":["code","design","test"]}`；也支持 number、integer、object、array 和嵌套字段。全部字段必填，不接受额外字段；节点从原有 output 文本末尾解析完整 JSON 对象或 JSON 代码块，忽略前面的过程说明；结果位于 `{{review.output.passed}}` 等变量中。格式不匹配时停止，点击“重试失败节点”重新调用，不会自动跳过校验。
- 代码：选择代码模式，填写绝对工作目录及允许修改的相对文件路径，每行一个（最多 30 个）。通过节点适配层复用已有的 agent.menu.code.start.v1 能力（沿用历史接口名称），保留 AI 插件已有的文件检查、目录互斥和原生人工确认；不自动批准 Agent 请求。
- 路由：添加“条件路由”。条件模式输出 true / false；分支值模式直接读取如 `{{review.output.route}}`。从路由节点连向各后续节点，点击连线填写对应分支值。只执行命中路径，未命中分支被跳过；多路结果可接“结果汇总”节点。
- 循环：添加“条件循环”，输入如 `{{test.output.passed}}`，条件为“等于 false”。continue 连回需要重新执行的处理或 Agent 节点，exit 连到后续节点；禁止返回数据输入或开始节点。最大轮次为 1–100，达到后等待选择继续下一组或退出；可随时停止。
- 每轮重新调用 Agent，清除返回目标及下游的旧结果，保留循环体外已完成节点。`{{loop.iteration}}` 是当前重入轮次，`{{loop.previous}}` 是上轮结果，具体字段如 `{{loop.previous.test.output.issues}}`。首轮 previous 为空对象，需要上一轮材料时映射整个 previous 对象。

例如：需求输入 → 产品 Agent（需求分析）→ 开发 Agent（方案设计）→ 开发评审 Agent → 产品评审 Agent → 测试评审 Agent → 路由 → 开发 Agent（编码）→ 测试 Agent → 循环 → 产品 Agent（验收）。评审通过字段用于路由，测试未通过则 continue 返回编码，修复节点通过 previous 读取测试问题。需要返回方案设计时，将评审结果交给循环节点判断。

当前沿用顺序执行，多个评审节点依次执行并通过输入映射共享结果。循环和显式重试可能再次执行代码或外部操作，不回滚已经发生的写入；重启后保留历史，不自动重放中断运行。

## 消息接入

1. 展开“消息连接”，新增连接。列表不返回密钥；编辑时密钥留空会保留原值。
2. 在“数据输入”中选择“微信消息”或“飞书群消息”，选择相应连接，配置筛选，再连接处理、Agent、人工确认或输出节点。
3. 每个工作流只允许一个消息入口，不能混用普通开始或定时触发。将触发方式设为“消息监听”，勾选启用并保存；初始默认关闭。普通运行按钮只提示开启监听。
4. “测试连接”只登录和显示状态，不制造消息。断开会暂停接收及排队派发；重连或重新启用插件恢复。查看队列和运行区，人工确认仍须用户提交。

### 个人微信（Wechaty）

需要支持个人微信的 Wechaty Puppet Service 服务与其 Token；可选端点格式为 `域名:端口`。本插件使用 TLS，不提供关闭 TLS 的开关。服务种类及 Token 由服务提供方配置，参见 [Wechaty 官方说明](https://wechaty.js.org/docs/puppet-providers/service/)。
填写 Token 后测试连接，在本地生成的二维码处扫码登录；状态会显示已登录账号或脱敏错误。支持私聊、群聊文本，忽略自身发送的消息。

### 飞书群

在飞书开发者后台创建自建应用并启用机器人，填写 App ID / App Secret。事件订阅选择长连接，订阅 `im.message.receive_v1`，发布应用并将机器人加入目标群。接入方式见 [官方 Node SDK](https://github.com/larksuite/node-sdk) 与 [事件订阅说明](https://open.feishu.cn/document/server-docs/event-subscription-guide/overview)。
授予所需的接收消息权限：仅接收群内提及机器人时使用 `im:message.group_at_msg`；接收全部群消息需应用实际获批相应权限（如 `im:message.group_msg`）。权限及发布状态决定机器人实际可见的事件。
节点默认“仅提及机器人”，关闭只改变本地筛选，不能扩大应用权限。首版仅支持群文本，不接收飞书私聊。

## 运行和恢复

- 会话 ID、发送人 ID 白名单为空表示不限；同字段多个值任一匹配，不同字段同时满足；关键词为普通子串。仅接收文本，不拉历史、不下载附件、不自动回复。
- 同连接的多个工作流共享一个监听，每个匹配工作流各接收一份；同一工作流串行，不同工作流可独立运行。Agent 后台轮询只读取状态，不代答问题或批准操作。
- 去重按连接、消息、工作流保留 24 小时，最多 10,000 条；每个工作流最多 100 条待执行消息，超限显示拒收；单条文本最多 64 KiB；终态历史每个工作流最近保留 20 条。
- 消息先持久化再派发。重启后已领取项显示“中断”，不会自动重复执行；确认外部结果后可手动重新运行。修改入口身份会使旧排队项失效。清空不影响活动任务，重新运行可能重复外部写入，操作前有确认。
- 最小化或关闭部分窗口仍可后台运行；确认关闭最后窗口、禁用或退出会停止监听并取消活动 Agent。插件 `loadOnStartup:false`，重启桌面后须手动打开/启用插件才恢复监听。
- 连接、会话、队列和消息运行快照保存在桌面的 `plugin-data/work-flow/`。凭据仅本地保存，接口不回传原值，日志不记录正文或凭据；本地数据包含消息正文，请按需保护与清理。

## 构建与验证

在仓库根执行 `node plugin-dev/work-flow/build/build.mjs`，使用插件自身锁文件安装生产依赖，再通过标准完整性打包。SDK、gRPC 资源及许可证随包分发；不包含测试、构建脚本或登录数据。
测试使用最新、版本匹配的 DeckPg 安装包和临时数据目录。离线模拟覆盖连接、筛选、队列、Agent 人工确认和停止协调；未提供真实账号配置时，真实收信仍需联调。

消息连接展示订阅工作流数、收到/入队/忽略/拒收计数及最近消息 ID、会话 ID、发送人 ID 和时间；计数随本次插件后台会话累计，重新打开最后窗口后从零开始，队列仍持久保留。无效/超长消息与入队失败可见，未落盘的消息不计入成功收到/入队。群名称缺失时不查询远端名称，不影响按稳定 ID 接收。
