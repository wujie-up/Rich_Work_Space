# 工作流编排 0.5.70

工作流领域属于本插件，Agent 能力通过工作台调用 ai-agent 插件。普通节点、邮件和菜单初始化操作见 `title.md`。
分发产物：`plugin-dev/dist/work-flow-0.5.70.plg`。插件清单、package 与锁文件版本统一为 0.5.70，宿主无需升级。

## 工具栏定时开关（0.5.70）

工具栏时钟可双向切换：未开启时提示“开启定时”，开启后变绿并提示“关闭定时”，同时提供准确的按下状态。
关闭仅停止后续自动触发，不中止正在执行的这一次；执行中仍可操作定时开关，当前运行由独立停止按钮控制。
关闭定时不会提交或丢弃本窗口未保存的画布编辑；开关状态随其他窗口的配置更新同步。立即触发仍只执行一次。

## 定时启用图标（0.5.69）

已开启定时的工作流在列表中显示绿色时钟，复用明暗主题各自的启用色；悬停与可访问名称继续说明定时状态。

## 开启定时与紧凑运行记录（0.5.66）

定时工作流顶部原“运行”按钮改为时钟图标，悬停显示“开启定时”，仅启用并保存定时配置；重复开启不重置原排期。
后台读取最新定义后仅更新启用状态，避免多个窗口之间的旧配置覆盖；本窗口尚未保存的编辑仍先按原保存流程处理。
需要测试时使用旁边的“立即触发”，它执行一次且不改变定时安排。仅手动工作流仍使用普通运行按钮执行一次，已到期任务沿用既有补跑规则。
最近运行改为按开始时间倒序的单行记录，展示完整时间、状态及靠右排列的会话/续跑操作；失败原因可悬停查看，详细结果仍保留。

## 升级后界面资源缓存修复（0.5.64）

构建后的界面入口按插件版本引用脚本和样式，避免同一桌面升级插件后加载缓存的旧事件处理代码。
真实桌面回归覆盖从 0.5.62 升级、关闭重开保留未来排期，以及关闭期间到期任务补跑；等待定时时显示时钟，实际执行才显示运行图标。

## 定时状态事件修复（0.5.63）

定时状态事件改用 `{ items: [...] }` 对象承载列表，适配宿主转发时注入插件 ID 的既有协议，修复启用定时后立即执行出现的 `state.triggers.find is not a function`。
回归测试通过真实宿主事件接收函数转发，覆盖启用、立即触发、取消和再次启用；工作流定义、执行表和历史格式不变。

## 定时状态、立即触发与重启补跑（0.5.62）

已保存并启用的定时工作流在列表显示时钟图标；实际执行和等待确认继续使用原运行状态图标，两者可同时显示。
选择定时工作流后，顶部新增“立即触发”图标按钮（悬停提示），便于测试；它不改变原定时排期，已有运行时禁止重复触发。
运行方式区显示下次运行、最近执行时间和状态。

后台执行表保存于 `plugin-data/work-flow/scheduled-tasks.json`，按工作流记录配置、下次排期、最近运行 ID、开始/结束时间、状态、错误及定时/手动来源。
插件启动后自动恢复原排期，到期未执行的任务立即补跑一次，多次漏跑合并一次；未来任务保持原时间，不重新计时。
单次任务已启动后不因重启重复提交；已启动但中断的运行保留历史，仍由用户核对外部结果后手动继续。
桌面重启后仍需首次打开插件（沿用按需加载），才会进行上述检查。禁用自动触发后不补跑；停止插件或删除流程会使在途触发失效。

## 工作流分组

左侧“工作流”标题旁的文件夹加号新建分组；空分组独立保存，升级和重启后仍保留。分组内的加号可直接创建属于该组的工作流草稿。顶部名称旁的分组图标可将当前工作流移入已有分组或移回“未分组”，确认后立即保存分组关系，不保存未提交的名称、节点或连线修改。新建草稿仍需点击保存才能保存流程定义。

组名旁的铅笔重命名整个分组，垃圾桶删除分组。删除时先显示成员数量并二次确认，成员全部移入“未分组”，保留工作流内容、运行进度及历史记录。删除或移走最后一个工作流不会自动删除空分组。名称去除首尾空白，不能为空或与已有分组重名；取消、Esc、点击外部不修改数据，保存失败显示原因。

点击组名展开或收起，折叠状态随分组保存；改名后保留状态。长名称省略显示，悬停可查看全名。分组仅组织列表，不改变画布、运行中的任务或暂停快照。删除工作流沿用单独的删除确认，不等于删除分组。

旧版本的名称分组自动兼容，首次写入时保存独立分组标识。工作流仍按单个流程导入导出，使用便携的分组名称；导入时同名加入已有组，否则新建组。未分组的旧文件继续兼容，空组和折叠状态不包含在单流程导出文件中。

## Agent 流水线

在“AI 能力”中添加“Agent 任务”，通过角色提示词区分产品、开发、评审与测试。节点仍由工作台调用 AI Agent 插件；复用既有任务接口，无需为工作流升级或扩展 AI Agent。角色、输入映射及输出解析均属于本插件的 Agent 节点。

- 输入：直接填写文本，或填写输入映射 JSON，例如 `{"requirement":"{{source.text}}","design":"{{design.output}}"}`。使用画布节点的实际 ID；完整变量引用保留对象、布尔和数字类型。
- 输出：留空保持原有文本输出。固定字段示例 `{"passed":"boolean","summary":"string","issues":"string[]","route":["code","design","test"]}`；也支持 number、integer、object、array 和嵌套字段。全部字段必填，不接受额外字段；节点从原有 output 文本末尾解析完整 JSON 对象或 JSON 代码块，忽略前面的过程说明；结果位于 `{{review.output.passed}}` 等变量中。格式不匹配时停止，点击“重试失败节点”重新调用，不会自动跳过校验。
- 代码：选择代码模式，填写绝对工作目录及允许修改的相对文件路径，每行一个（最多 30 个）。通过节点适配层复用已有的 agent.menu.code.start.v1 能力（沿用历史接口名称），保留 AI 插件已有的文件检查、目录互斥和原生人工确认；不自动批准 Agent 请求。
- 路由：添加“条件路由”。条件模式输出 true / false；分支值模式直接读取如 `{{review.output.route}}`。从路由节点连向各后续节点，点击连线填写对应分支值。只执行命中路径，未命中分支被跳过；多路结果可接“结果汇总”节点。
- 循环：添加“条件循环”，输入如 `{{test.output.passed}}`，条件为“等于 false”。continue 连回需要重新执行的处理或 Agent 节点，exit 连到后续节点；禁止返回数据输入或开始节点。最大轮次为 1–100，达到后等待选择继续下一组或退出；可随时停止。
- 每轮重新调用 Agent，清除返回目标及下游的旧结果，保留循环体外已完成节点。`{{loop.iteration}}` 是当前重入轮次，`{{loop.previous}}` 是上轮结果，具体字段如 `{{loop.previous.test.output.issues}}`。首轮 previous 为空对象，需要上一轮材料时映射整个 previous 对象。

例如：需求输入 → 产品 Agent（需求分析）→ 开发 Agent（方案设计）→ 开发评审 Agent → 产品评审 Agent → 测试评审 Agent → 路由 → 开发 Agent（编码）→ 测试 Agent → 循环 → 产品 Agent（验收）。评审通过字段用于路由，测试未通过则 continue 返回编码，修复节点通过 previous 读取测试问题。需要返回方案设计时，将评审结果交给循环节点判断。

当前沿用顺序执行，多个评审节点依次执行并通过输入映射共享结果。循环和显式重试可能再次执行代码或外部操作，不回滚已经发生的写入；重启后保留历史，不自动重放中断运行。

## 消息接入

1. 展开“消息连接”，新增连接。列表不返回密钥；编辑时密钥留空会保留原值。
2. 在“数据输入”中选择“微信消息”或“飞书群消息”，选择相应连接，配置筛选，再连接处理、Agent、人工确认或输出节点。
3. 每个工作流只允许一个消息入口，不能混用普通开始或定时触发。将触发方式设为“消息监听”，勾选启用并保存；初始默认关闭。普通运行按钮只提示开启监听。
4. “测试连接”只登录和显示状态，不制造消息。断开会暂停接收及排队派发；重连或重新启用插件恢复。查看队列和运行区，人工确认仍须用户提交。

### 个人微信（Wechaty）

需要支持个人微信的 Wechaty Puppet Service 服务与其 Token；可选端点格式为 `域名:端口`。本插件使用 TLS，不提供关闭 TLS 的开关。服务种类及 Token 由服务提供方配置，参见 [Wechaty 官方说明](https://wechaty.js.org/docs/puppet-providers/service/)。
填写 Token 后测试连接，在本地生成的二维码处扫码登录；状态会显示已登录账号或脱敏错误。支持私聊、群聊文本，忽略自身发送的消息。

### 飞书群

在飞书开发者后台创建自建应用并启用机器人，填写 App ID / App Secret。事件订阅选择长连接，订阅 `im.message.receive_v1`，发布应用并将机器人加入目标群。接入方式见 [官方 Node SDK](https://github.com/larksuite/node-sdk) 与 [事件订阅说明](https://open.feishu.cn/document/server-docs/event-subscription-guide/overview)。
授予所需的接收消息权限：仅接收群内提及机器人时使用 `im:message.group_at_msg`；接收全部群消息需应用实际获批相应权限（如 `im:message.group_msg`）。权限及发布状态决定机器人实际可见的事件。
节点默认“仅提及机器人”，关闭只改变本地筛选，不能扩大应用权限。首版仅支持群文本，不接收飞书私聊。

## 运行和恢复

- 会话 ID、发送人 ID 白名单为空表示不限；同字段多个值任一匹配，不同字段同时满足；关键词为普通子串。仅接收文本，不拉历史、不下载附件、不自动回复。
- 同连接的多个工作流共享一个监听，每个匹配工作流各接收一份；同一工作流串行，不同工作流可独立运行。Agent 后台轮询只读取状态，不代答问题或批准操作。
- 去重按连接、消息、工作流保留 24 小时，最多 10,000 条；每个工作流最多 100 条待执行消息，超限显示拒收；单条文本最多 64 KiB；终态历史每个工作流最近保留 20 条。
- 消息先持久化再派发。重启后已领取项显示“中断”，不会自动重复执行；确认外部结果后可手动重新运行。修改入口身份会使旧排队项失效。清空不影响活动任务，重新运行可能重复外部写入，操作前有确认。
- 最小化或关闭部分窗口仍可后台运行；确认关闭最后窗口、禁用或退出会停止监听并取消活动 Agent。插件 `loadOnStartup:false`，重启桌面后须手动打开/启用插件才恢复监听。
- 连接、会话、队列和消息运行快照保存在桌面的 `plugin-data/work-flow/`。凭据仅本地保存，接口不回传原值，日志不记录正文或凭据；本地数据包含消息正文，请按需保护与清理。

## 工作流导入、导出与修改

顶部的导出图标将当前编辑内容（包括尚未保存的修改）输出为独立 `.workflow.json` 文件。先选择保存目录；导出不保存或改变当前流程。文件保留名称、节点能力、参数、角色提示词、输入输出映射、连线、布局及触发定义，不包含流程 ID、运行记录、暂停快照或本地账号数据。参数中的文本、路径及用户自行填写的敏感内容仍会保留，分享前请检查文件。

点击导入图标选择 JSON，预览流程名称和节点数。默认新建独立流程，也可选择更新已有流程；更新需要二次确认，会替换该流程的定义及尚未保存的编辑，保留 ID、创建时间、历史记录和暂停快照。运行中或等待用户的流程不能覆盖，先暂停或结束。暂停运行继续使用原快照中的定义，新运行使用导入后的定义。取消选择或预览不会写入数据。

导入始终设为手动运行，清除邮件账号和消息连接的本地引用，并提示重新选择；不会自动执行或开启监听。导入后可直接在画布和右侧属性面板修改，再保存或导出，无需重新打包插件。文件最大 10 MB；不支持的版本、未知节点或无效连线在导入前报错。

JSON 格式为 `{"format":"deckpg.workflow","version":1,"workflow":{"name":"流程名称","nodes":[],"edges":[],"trigger":{"mode":"manual"}}}`。节点和连线使用当前画布的数据结构。

内置模板仅首次初始化时创建；升级、重启不再自动改写已保存的模板，也不会重新创建已删除的模板。后续模板内容以 JSON 分发，由用户选择新建或更新。

## 通用自定义节点

“添加节点 → 数据处理 → 自定义节点”支持配置数据处理、MCP工具调用、Markdown报告及JavaScript/Python脚本，同一种节点通过名称和配置适配不同业务。统一从上游变量取得输入，结果从 `{{节点ID.value}}` 读取；多个输入可填写输入映射JSON。配置/代码随工作流导入导出，无需为新业务注册节点类型。

脚本填写函数体，input为映射输入，配置JSON为params。例如JS：`return input.filter(row => row.status === params.status);`；Python：`return [row for row in input if row['status'] == params['status']]`。代码不做模板插值。Python可选择本机解释器路径，缺失时明确报错，不自动下载依赖。JS使用工作台运行时。

脚本为可信本地代码，可访问本机资源；独立进程不是权限沙箱。超时/取消/退出清理当前进程组，不继承完整父环境或自动注入凭据；大整数ID用字符串。默认30秒，上限300秒；输入1MiB、结果4MiB、单路日志64KiB，超限报错。MCP使用已有授权通道，SQL字段使用类型化绑定，截断结果必须分页，失败不自动重试。
