# 会话组实施计划（已选左侧导航）

场景：同一工作台中，多个 Agent 按任务组协作。主要矛盾是通信目前以窗口为边界，缺少稳定的任务组身份，发现范围和自动投递难以控制。

范围：仅 AI Agent 插件。复用现有终端、宿主消息通道、公共弹窗及输入安全保护。

1. 新增持久化组记录；会话保存 groupId，恢复、分叉与清理上下文保留组身份。
2. 后台发现与发送限定同组；未分组不参与自动协作，已有跨组队列不自动执行。
3. 左侧组/成员导航；居中创建组，指定成员数量、名称及引擎；右侧标题带组名。切组保留终端与任务。
4. 扩展现有队列验证：空闲自动提交、忙碌 FIFO、草稿和确认保护；补充组隔离、持久化及界面验证。
5. 实际模型验证后构建 0.6.83 包；检查明暗主题、窄窗口、焦点与恢复。未经实际运行的部分明确列出。

验收：同组可发现、跨组不可发送；创建 N 名成员产生 N 个带组名的窗口；恢复后组身份不变；切组不重建终端；空闲消息自动提交且忙碌完成后继续；保留既有会话历史与布局。

0.6.83 验证（2026-10-31，历史记录）：

- 受影响领域与直接关联契约共 79 项测试通过，覆盖组隔离、失败回滚、投递竞态、恢复、终端队列及文本确认。
- Electron 验证居中创建、切组保留终端、折叠与最大化恢复、焦点、禁用、明暗主题及 420px 窄窗口；后台组的问题弹窗不会抢焦点，回答草稿保留。
- Codex 0.166.0 / gpt-6.1-sol 与 Claude Code 2.1.312 / DeepSeek 均实际调用组内发现和发送工具；真实接收模型自动执行空闲消息，忙碌时两条消息保持排队，结束后按 FIRST、SECOND、THIRD 顺序自动执行。
- 真实模型在隔离的临时数据目录验证；测试只预先授权临时证明文件、短暂等待及会话通信工具，未修改安装配置或历史。未安装到用户当前工作台。
- 0.6.83 已构建，标准 gzip tar 包的 100 个文件及 SHA-256 清单校验通过，未包含开发依赖、测试产物或用户数据。

## 0.6.90：固定协调者与本地优先通信

场景：组内执行成员分工工作，由独立协调者跟进任务。主要矛盾是等待、状态同步和进度回传容易变成模型之间反复对话，既消耗上下文，又不能保证成员持续反馈。

范围仍为 AI Agent 插件，复用工作台已有本地消息通道、文件副本和终端队列，不修改宿主协议。

- 每组额外创建一个固定“协调者”，具有独立引擎上下文，可单独选择引擎。执行成员数量不包含协调者。侧栏优先展示协调者，不允许单独关闭、移出、归档或删除；删除整个组仍保留各会话及历史。旧组在打开成员时补建独立协调者，逻辑身份随升级和恢复保留。
- 任务开始后显示“协调中”，原生终端仍按实际忙闲判断投递。本地巡检承担等待工作，无需模型持续生成或轮询；任务完成由协调者调用 `agent_group_task(complete)`。
- `agent_sessions_list` 读取本地成员状态与精简进度；`kind=progress` 仅保存每位成员的最新摘要，返回本地 recorded 回执，不写入接收方输入框。协调者可以查询全组摘要，普通成员只返回自己的进度，不传递内部重试台账。
- `task`、`result`、`blocked` 使用既有本地队列提交必要内容，默认发送保留兼容。优先短摘要及本地文件附件，不自动转发完整对话或文件正文。只有模型需要执行或决策时，必要内容才进入目标模型。
- 本地每 10 秒检查一次；分派任务已投递且超过 60 秒未收到反馈时，生成一条固定简短追问，忙碌时排队、空闲后自动提交。直接输入给执行成员的任务也纳入跟进，但原始输入不转发给协调者。每次反馈更新前最多一条追问，避免持续模型空转。
- 离线或等待用户确认时暂停追问；通道失败重试沿用持久化请求 ID。新进度或任务结束后，过期追问在提交前丢弃。旧进度、任务及结果回执重试不会覆盖新进度、重启已完成任务或清掉新任务；回复追问时通过本地记录关联原任务。

验收指标与本轮证据（2026-10-31）：

- 后台 100 项相关测试通过：固定成员保护、旧组迁移及并发补建、升级归档与恢复、本地进度零目标终端写入、超时只追问一次、断线重试去重、重启恢复、草稿/确认保护、忙碌 FIFO 与空闲自动投递、存储失败不发布未提交状态。
- Electron 会话组综合用例通过：协调者独立引擎、只读角色名、侧栏首位、关闭/移组禁用、逻辑协调状态不伪造终端忙碌；并回归居中弹窗、键盘、明暗主题、窄窗口、导航、折叠和最大化恢复。
- 本轮使用真实工作台通道与模拟终端验证投递链路，未重跑云端真实模型调用；上面的 0.6.83 模型验证不能作为本版本的新验收结果。未安装到用户当前工作台。
- 0.6.90 已重新构建并通过宿主打包命令生成标准 gzip tar 包，101 个文件的 SHA-256 清单校验通过；包内协调、队列、分组及会话源码与本次源码一致，不包含开发依赖、测试或用户数据。独立只读评审复核了旧进度重试、旧任务重放及追问回复关联三个边界，未发现新增高/中优先级问题。


## 0.6.91：开始协调前明确终止条件

场景：用户向固定协调者提交新任务。主要矛盾是任务缺少明确的停止边界时，分工与跟进可能持续进行，无法按用户意图判断何时结束。

范围仅限 AI Agent 插件的协调逻辑、通信工具参数及对应测试，不修改宿主通道或执行成员的原有主流程。

- 协调者收到新任务时，必须先收集用户明确提供的终止条件；没有条件时先追问并等待，不得自行假定、执行或派单。任务中已明确包含条件时直接记录，无需重复追问。
- `agent_group_task(start)` 必须填写非空且不超过 2000 字的 `terminationCondition`，本地持久化后才允许协调者发送任务。协调者单纯收到用户输入不再自动启动组任务。
- 精简任务摘要包含终止条件，重启后继续保留；满足条件或用户要求停止时调用 `complete`，同时清除条件，下一项任务需要重新提供。

本轮实际验证（2026-10-31）：102 项相关后台测试通过，覆盖缺失/空白/错误类型/超长条件拒绝、持久化恢复、缺少条件禁止派单、记录后自动投递及任务完成后禁止沿用条件。未修改界面，未重跑 Electron 或云端真实模型验证，未安装到当前工作台。原生模型执行行为依赖协调者角色指令；后台强制校验覆盖组任务启动和协调者派单入口。

## 0.6.92：成员直接交接下一执行者

场景：组内成员完成一个步骤后，下一执行者已经明确。主要矛盾是全部经协调者转发增加模型往返，原本允许的成员直连又未纳入本地任务跟进。

- 调整角色、工具及消息输入提示：明确下一执行者时直接交接，`kind=task`，`replyTo` 关联当前任务；结果直接回复请求方。职责不明、分工冲突、无法自行解决的阻塞及全组最终汇总再交协调者，保留用户终止条件要求。
- 复用既有本地任务台账，记录直接交接的发送者与接收者；显式交接只替换关联的原任务，其他并行任务保留。结果按请求方及原任务匹配完成；重试去重、持久化恢复与旧台账兼容继续生效。
- 本地巡检从实际发送者读取投递回执，必要时向新执行者追问，不唤醒协调者模型。普通进度仍只写本地，任务和附件沿用工作台通道、忙碌排队与空闲自动提交。

本轮实际验证（2026-10-31）：105 项相关后台测试通过。新增三成员真实工作台通道与模拟终端用例，覆盖文件直传、忙碌排队、空闲后自动提交、结果直接返回且协调者零终端写入；另覆盖交接只转移关联任务、并行任务保留、重试去重、重启恢复、按实际发送者查询回执及巡检回复关联。并行测试首轮出现既有临时目录清理的 ENOTEMPTY，串行执行上述领域用例后全部通过，未扩展修改清理逻辑。未重跑云端真实模型或 Electron，未安装到当前工作台。

## 0.6.94：可选协作模式与组长入口（成员输入行为于 0.6.142 更新）

场景：会话组既用于整理独立窗口，也用于共同完成任务。主要矛盾是所有组强制协作会创建不需要的协调窗口、开放通信并分散用户输入入口。

范围仅为 AI Agent 插件的分组、通信、角色指令、终端输入呈现及直接关联测试，复用已有宿主本地通道，不修改宿主。

- 新建会话组默认关闭“协作模式”：仅创建指定成员，不创建组长、不注册通信端点或工具、不启动巡检，各窗口保留输入区。已有组迁移为开启，保持原有协作能力。
- 开启后额外创建固定“组长会话”；标题使用“组名 · 组长/成员名”，组长入口显示“输入团队任务…”。所有成员均保留原生输入区、文件引用及离线草稿，可直接输入任务或回答问题，无需切换人工介入。
- 本地查询、进度和去重回执不唤醒接收模型；任务、结果和阻塞沿用本地队列，在接收模型需要处理时提交。明确下一执行者时直接交接，不经组长重复转发。
- 两类角色均要求精简准确：传目标、必要约束、文件位置和验收条件；回传结论、关键依据、实际验证与未解决项。长内容留在本地文件，避免重复背景、无变化进度及确认收件的模型往返；不得省略关键限制、风险、失败或不确定性。

0.6.94 历史验证（成员输入限制已于 0.6.142 移除）：101 项相关后台测试通过，覆盖分组迁移、通信隔离、本地进度、队列、巡检、恢复及角色指令；3 项 Electron 综合用例通过，覆盖开关两种创建流程、组长保护、成员输入限制、原生终端响应、权限审批、明暗主题、窄窗口及拉伸/折叠/最大化恢复。额外检查成员终端截图像素，确认拉伸后历史仍可见且原生输入区隐藏。未重跑云端真实模型，因此精简指令对实际输出长度的影响尚未量化；未安装到当前工作台。

0.6.142 验证（2026-11-03）：76 项相关后台测试、6 项针对性 Electron 测试通过，覆盖直接输入、文件引用、草稿保护、组内通信、任务交接、终端缩放及简洁视图的明暗主题与窄窗口。扩展检查的拖拽超时、离线状态选择器冲突及通信夹具缺少协作配置三项失败，均在修改前源码副本复现；未修改范围外逻辑。插件构建和完整性校验通过，未安装到当前工作台，未调用真实云端模型。

### 会话组归档（本轮）

场景：保留可恢复上下文的整组生命周期管理。主要矛盾是关闭全部窗口后，通信与组长巡检仍可能唤起成员。

范围限定 AI 插件：增加组归档标记，持有成员输入队列后检查空闲及协作任务；有任务时拒绝并提示先停止任务。
归档保留组关系和窗口历史，暂停通信、自动恢复及巡检。历史按组折叠，支持整组串行恢复和单窗恢复，复用现有进度与恢复队列。

验收：忙碌组不关闭任何窗口；归档重载后不自动启动；显式恢复保留上下文与成员关系；历史分组与明暗主题、窄窗口可用。
