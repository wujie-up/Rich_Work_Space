# 消息对接 · 0.1.3

独立插件，将所选渠道中命中前缀、关键词或 @ 的消息提交给 AI Agent，再把本轮最终文本回复到原聊天。支持选择已有结构化 Agent 会话，或按“渠道＋聊天＋发送者”创建并持续复用只读专属会话。旧配置中的白名单及共享上下文仍按原语义生效。

渠道协议、扫码、关键词规则、来源映射与回传全部归属本插件；通过宿主 `desk.capabilities.v1` 调用 AI 插件已有会话能力，不导入 AI 插件内部实现，不要求 Agent 处理 IM 协议。

## 配置步骤

1. 安装配套 AI Agent 插件及本插件，启用需要的 AI 引擎并完成其独立登录。
2. 在本地窗口点击“授权 Agent 桥接”，处理宿主的授权提示。
3. 新增并启用渠道；本机微信先完成原生网关准备，再连接网关。其他扫码渠道在手机确认后显示连接状态与账号。平台拒绝登录时直接显示错误码和原因。
4. 新增规则，选择渠道、触发方式与内容（默认 `@小微`）和目标会话；专属会话可配置引擎及工作目录。无需填写规则名称、聊天或发送者 ID。
5. 发送 `@小微你好` 或 `@小微 请总结以下聊天记录` 并粘贴多行聊天文本。前缀后的文本交给 Agent，结果在原渠道、原聊天返回；任务状态在“运行记录”查看。

飞书：创建自建应用机器人，填写 App ID / App Secret；配置长连接接收 `im.message.receive_v1`，申请消息发送、机器人单聊接收、群 @ 接收等实际所需权限，发布应用并加入目标群。接收普通群消息还需平台对应权限。无需公网回调地址。参考 [飞书事件与权限](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)。

微信专用机器人：选择 iLink，保存后点扫码登录。使用腾讯公开的机器人协议，当前适配仅承诺专用私聊；不将协议里的群字段视为普通群能力。重新扫码会关闭旧账号交互并清除旧回复上下文。参考 [腾讯协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md)。

微信好友／现有群及专用机器人账号：新增 Wechaty 渠道默认选择“Mac 本机客户端 · 原生网关”。需先准备兼容的本机 Wechaty gRPC 网关，填写网关 Token（不是工具激活码），端点留空使用 `127.0.0.1:18401`，保存后点击“连接本机微信网关”。只有 SDK 收到登录事件才显示已连接；端口未监听或认证失败会显示连接错误。插件支持回环 IPv4、localhost 及 `[::1]:端口`，本机连接使用明文 gRPC，远程渠道仍使用原有 TLS。

可选网关 [wechat-use](https://github.com/leeguooooo/wechat-use) 当前要求 Apple Silicon Mac、独立登录的微信 4.1.9 副本及个人非商业激活；主微信 4.1.15 正常登录不代表该网关已可用。按其[专用客户端准备文档](https://github.com/leeguooooo/wechat-use/blob/main/docs/managed-419-setup.md)完成设置、读取和发送就绪检查，再启动 `wechat-wechaty-gateway` 并配置独立网关认证。插件不包含、下载或执行该第三方工具，不修改主微信，也不要求 Agent 安装微信 skill。其他兼容的本机 Puppet Service 网关同样可用。

原有网页渠道保持“微信网页协议 · 扫码登录”，使用 `wechaty-puppet-wechat4u@1.14.14`，无需 Service Token 或浏览器。账号须有网页接口登录资格；错误 1203 不能通过本机连接选项直接消除，需另行准备原生网关。[Wechaty WeChat4U](https://wechaty.js.org/docs/puppet-providers/wechat4u/)。

已有 Puppet Service 配置继续有效，也可显式选择“Puppet Service”并填写 Token／服务端点；不会自动切换已有账号的接入方式。本机、网页和 Service 的登录状态分别保存，各渠道独立；切换渠道配置会关闭旧交互并保留 Agent 会话。切换账号或协议后联系人或群 ID 可能改变，旧白名单规则须从最近来源核对并更新，不以昵称自动替换身份。[Wechaty Puppet Service](https://wechaty.js.org/docs/puppet-services/)。

## 会话与恢复规则

- 已有会话须为支持原生轮次的结构化会话，保持页面打开、输入框为空且没有输入法组合；有草稿、忙碌或状态未知时排队。原生终端会话当前列出但不可选择，不能用终端静默猜测一轮完成。
- 已有会话沿用实际执行权限，绑定时须本地确认。专属会话固定为只读，仍可能请求本地权限确认；微信和飞书回复不会批准原生权限。
- 普通追问会收到 `/reply 短码 问题ID=答案` 提示；只接受原渠道、聊天、发送者在十分钟内的回答。
- 同一来源消息持久化去重；重启不自动重放提交结果不确定的任务。发送回执不确定时保留记录，核对原聊天后手动确认重发；固定客户端 ID 不代表所有平台保证幂等。
- 暂停规则只停止接收新任务；解绑、修改渠道或规则范围、撤销授权、停止插件会关闭旧交互，不在后续重新授权时发送旧结果。解绑保留 AI 会话历史，之后新消息会建立新绑定。
- 排队超时十分钟；运行超时三十分钟；追问等待十分钟；桥接进程租约一分钟。插件停止时只中断自身专属会话中对应的轮次，不中断用户已有会话的本地工作。
- 当前适配文本消息与文本结果；图片、语音和文件没有实现。群内回复对群成员可见；专属会话默认按聊天及发送者隔离，旧配置的共享上下文继续有效。

## 数据与验证

密钥、微信游标和原始回复上下文仅保存在本插件数据目录，遵循宿主文件权限；配置接口不会回传保存的密钥。启用渠道意味着监听账号可见范围的消息。新建规则按所选渠道和触发内容筛选；旧白名单规则在主动编辑保存前仍保持原范围，编辑后采用简化规则的渠道范围。相同优先级的重叠规则会拒绝转发，需要修改触发内容或停用重复规则。卸载默认保留数据。

运行 `npm test --prefix plugin-dev/message-bridge`，构建 `npm run build --prefix plugin-dev/message-bridge`。构建在临时目录安装锁定生产依赖，输出 `plugin-dev/dist/message-bridge-0.1.3.plg`，包含完整性清单，不包含账号数据。

常规测试使用独立临时目录、模拟平台协议和模拟原生引擎，不使用真实凭据。另可在仓库根目录执行 `node --test plugin-dev/message-bridge/test/wechat-web-network.fixture.mjs`：实际访问微信网页登录接口，连续三次取得二维码并关闭连接；不会扫码、登录账号或发送联系人消息。通过协议或二维码检查不代表真实账号上线通过；首次使用仍需完成扫码、平台权限与三类渠道的真实收发验收。

0.1.2 的登录回归还使用本地 HTTP 协议夹具驱动真实 Wechaty SDK，覆盖扫码、手机确认、HTTP 200/301 凭据解析、登录账号显示与平台拒绝；不使用真实账号，也不代替真实收发验收。

0.1.3 使用本地 gRPC PuppetServer、真实 Wechaty SDK、宿主能力协议和模拟 Agent 引擎验证私聊／群聊收发、前缀触发、重复消息去重、连续问题复用同一会话、错误 Token 及连接取消。网关中的联系人和消息均为夹具数据。真实 Mac 客户端收发尚未验收，需本机原生网关安装、激活且登录就绪后继续。

本机渠道的单次 gRPC 请求限时 5 秒，事件流持续监听；停止渠道会取消底层连接。发送超时仍按原有规则记为结果不确定，需要核对原聊天后手动确认重发。
